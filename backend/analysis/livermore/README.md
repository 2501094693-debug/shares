# 利弗莫尔交易思想：现行实现

本文说明系统里如何把杰西·利弗莫尔（Jesse Livermore）的交易思想落成可复现的规则引擎，而不是用大模型去“感觉该不该买”。

规则版本：`livermore-v1`  
代码目录：`backend/analysis/livermore/`  
研判入口：`/analysis?view=trend`

---

## 1. 要把哪几条思想变成机器

利弗莫尔留下的可操作部分不是估值公式，而是一套**由上而下的确认流程**：

| 思想 | 他怎么说 | 机器怎么做 |
|---|---|---|
| 先看大势 | 总体市场不对，个股再强也不做 | 上证指数走同一套六栏，不在上升家族则全场 `cash` |
| 追随领头羊 | 只做强势行业里的强势股 | 申万三级轮动 + 组内近 20 日涨幅前 20% |
| 等关键点 | 价格自己打穿前高 / 箱顶再动手 | 摆动高点、箱顶、52 周高；穿过才允许试探 |
| 时间要素 | 回撤耗多久和跌了多少一样重要 | 六栏切换日期、`reaction_days`、突破后跟踪 3～8 日 |
| 量能确认 | 走出来要有跟随，走不动是危险信号 | 突破日成交量 ≥ 近 20 日均量 × 1.3 |
| 试探、加码、认错、空仓 | 小仓试错，对了才加，错了立刻走 | 六个动作：`probe / pyramid / hold / wait / exit / cash` |
| 不碰死股 | 只要波动够、能走出趋势的股票 | 近 20 日 ATR% ≥ 1.2，且日均额 ≥ 3000 万 |

明确**不**写进开仓条件的：PE、财报、股东户数、公告、股吧热度、龙虎榜。那些属于另一条价值投资链路。

也不用 LLM 决定动作。巴菲特 / 八看是「规则算表 → 模型写研报」；利弗莫尔的终点是仓位动作，必须可回测、可复盘。解释层以后再加，且禁止改写 `action`。

## 2. 总体架构

实现放在现有研判模块里，和阴跌/横盘（`grind`）、行业轮动（`rotation`）同一套：配置、计算、后台任务、落盘、HTTP、前端页签。

```
日 K（前复权认趋势，不复权认心理价）
        │
        ▼
  key.py 六栏状态机  ──►  上证：gate.py 总闸
        │
        ▼
  pivot.py 关键点 + volume.py 量能 + follow.py 跟随
        │
        ▼
  screen.py 叠行业轮动、组内相对强度
        │
        ▼
  action.py 输出动作（禁止模型改写）
        │
        ├── GET /api/screen/livermore
        ├── GET /api/screen/livermore/stock
        └── 研判页「趋势分析」
```

| 文件 | 职责 |
|---|---|
| `config.py` | ATR 倍数、活跃度门槛、规则版本 `lv1` |
| `bars.py` | 清洗日 K；前复权与不复权按日期对齐 |
| `atr.py` | 20 日真实波幅（SMA，便于回放） |
| `key.py` | 六栏市场记录 |
| `pivot.py` | 关键点及 approaching / cleared / failed |
| `volume.py` | 突破量比、回撤缩量 |
| `follow.py` | 穿过后 3～8 日跟随 / 滞涨 / 失败 |
| `strength.py` | 个股 vs 上证、vs 本三级 |
| `gate.py` | 大盘是否允许新开多 |
| `action.py` | 六个动作与原因码 |
| `engine.py` | 单指数 / 单股诊断 |
| `screen.py` | 全市场扫描与二次装配 |
| `service.py` | 后台任务 + 落盘，盘中复用当日结果 |
| `test_engine.py` | 六栏、闸门、补涨股等待等单测 |

数据复用，不另接行情源：

- 个股日 K：`company.line.fetcher.fetch_kline`（腾讯优先，东财兜底）
- 上证指数：必须用 `SH000001` 直拉，避免被规范成平安银行 `000001`
- 股票池与申万归属：`industry.stocks`
- 领头行业：只读轮动缓存 `analysis.persist` 的 `rotation_d20_s9`，不在趋势扫描里重跑轮动

全市场扫描为了速度默认只拉前复权日 K；单股诊断（CLI 或 `/stock`）会再拉不复权，用来认整数关。

## 3. 六栏：把「趋势 + 时间」写成状态机

利弗莫尔 1940 年的 Market Key 用约 6 个点确认自然回撤、约 3 个点确认穿过关键线。A 股价格尺度不同，系统改成 **ATR 倍数**（近 20 日真实波幅的简单平均）：

| 1940 年 | 现行默认 | 含义 |
|---|---|---|
| 约 6 点 | `REACTION_ATR = 1.0` | 离开趋势高/低，记入自然回撤或自然回升 |
| 约 3 点 | `CONFIRM_ATR = 0.5` | 收盘穿过关键线，确认趋势恢复 |
| — | `REVERSAL_ATR = 2.0` | 从关键线再走出约 2 倍 ATR，趋势反转 |

七个栏目（第六栏加一个数据不足）：

| `column` | 中文 | 家族 `family` |
|---|---|---|
| `uptrend` | 上升趋势 | bull |
| `natural_reaction` | 自然回撤 | bull |
| `secondary_reaction` | 二次回撤 | bull |
| `downtrend` | 下降趋势 | bear |
| `natural_rally` | 自然回升 | bear |
| `secondary_rally` | 二次回升 | bear |
| `unclear` | 不明 | unclear |

上涨侧转移（下跌对称）：

1. 持续创新高 → 留在 `uptrend`，更新极值。**创新高的那一根不再用当天低点去切栏目**，避免上下影被当成回撤。
2. 其后某日低点距上升极值 ≥ 1.0×ATR → `natural_reaction`，并把离开时的高点记为 `key_up`（关键线）。
3. 收盘重新站上 `key_up + 0.5×ATR` → 回到 `uptrend`。
4. 从 `key_up` 再跌 ≥ 2.0×ATR 且收在回撤低点附近 → 翻成 `downtrend`。
5. 回撤中先反弹够 1.0×ATR、再第二次下探 → `secondary_reaction`。

时间要素挂在换栏上：`column_since`、`last_switch`、`reaction_days`。自然回撤只走了两天，不会被当成“等够了”；回撤满 8 天（`BOX_MIN_DAYS`）才把 `key_up` 升格为箱顶关键点 `box_high`。

上证和个股跑**同一套** `walk_key()`。这是「先看大势」的技术前提：大盘和个股用同一语言说话。

## 4. 关键点、量能、跟随

### 4.1 关键点种类

`pivot.py` 每日给出若干关键点，按与现价的 ATR 距离排序：

- `swing_high`：左右各约 5 根的摆动高点（前高）
- `box_high` / `key_up`：六栏离开上升趋势时的高点；回撤满 8 天升格为箱顶
- `high_52w`：近 250 根最高价
- `round`：不复权价附近的整数关（≥100 取 10，≥30 取 5，≥10 取 1，否则 0.5）

每个点有状态：`below` / `approaching` / `touched` / `cleared` / `held` / `failed`。

**整数关只作观察，不触发试探。** 现价 27.1、整数关 27，几乎永远是 `cleared`，若拿它开仓会把整套规则变成乱开。量能确认、跟随、失败检测都排除 `kind == round`。

### 4.2 量能

突破是否算数：最近一根成交量 / 此前 20 日均量 ≥ 1.3，并且当天存在非整数关的 `cleared`。  
另记回撤是否缩量（近 3 日均量 ≤ 20 日均量的 80%）、是否高潮量（量比 ≥ 3，只作标记，不当入场）。

### 4.3 跟随

关键点被穿过之后 3～8 个交易日：

- 收盘跌回关键点下方 0.3×ATR → `fail` → 动作倾向 `exit`
- 已过 3 日仍未创新高 → `stall` → 只能 `wait`
- 否则 `follow_ok` / `cleared`

这对应书里安纳康达铜业冲上 300 只到 302 就滞住、立刻离场的例子：穿过不等于趋势成立。

## 5. 由上而下的判决管道

全市场扫描分两遍，避免边算边改闸门。

**第一遍（纸带）**  
每只股票只根据自身日 K 算出：六栏、关键点、量能、跟随、近 20 日涨幅、活不活。此步不看行业、不看大盘。

**第二遍（装配 `assemble`）**

```
gate.py        上证六栏 ∈ {上升趋势, 自然回撤, 二次回撤} 才允许新开多
               自然回升 / 下降趋势 / 不明 → 全场 cash（下跌里的反弹不当新多）
      ↓
行业           优先读轮动最新一日的 first + again 三级代码
               没有轮动缓存时：本三级成分股 20 日涨幅中位数 ≥ 上证 20 日涨幅（代理）
               单股诊断样本不足时不因行业缺失而误杀（tag = unknown）
      ↓
strength.py    本三级内近 20 日涨幅排名进入前 20% 才算领头股
               同行不足 3 只则不做相对强度否决（避免单股诊断永远 wait）
      ↓
liveliness     ATR% ≥ 1.2 且日均成交额 ≥ 3000 万，否则 stock.dead → wait
      ↓
action.py      综合关键点、量能、跟随，输出唯一动作
```

设计意图：缺任何一层都不凑合开仓。分数只用于列表排序，不用于“差一点点也买”。

行业闸门依赖轮动缓存。要让「追随领头羊」更准，应先在研判页跑一次「行业行情分析」（20 日窗口），再扫趋势。

## 6. 动作规则（`action.py`）

六个值，前端按此筛选：

| 动作 | 含义 | 何时出现 |
|---|---|---|
| `cash` 空仓 | 今天什么都不做 | 大盘总闸关闭，或个股六栏 `unclear` |
| `wait` 等待 | 结构不对或还没穿过 | 死股、行业落后、组内补涨、靠近关键点未穿过、量能不足、跟随滞涨 |
| `probe` 试探 | 刚确认，相当于试探仓 | 非整数关已 `cleared`，量能过关，跟随未失败，穿过后 0～2 日 |
| `pyramid` 加码 | 趋势已在工作中再过新点 | 现行启发式：已在 `uptrend` 且换栏日期与「进入本栏」不一致时的新穿过；**没有真实持仓账户**，不能当成券商加仓指令 |
| `hold` 持有 | 趋势仍在、穿过已确认 | 穿过超过 2 日且 `follow_ok`，或上升趋势仍在 |
| `exit` 离场 | 关键点失败 | `follow=fail` 或关键点 `failed` |

止损参考（不是自动下单）：

- `invalidation`：关键点价格 − 0.3×ATR  
- `stop`：`min(收盘 − 1.2×ATR, invalidation)`

没有「摊平」动作。亏损方向不会加仓。

原因码（`reason[]`）便于复盘，例如：

- `gate.blocked` 大盘不允许新开多  
- `column.unclear` 六栏未成形  
- `stock.dead` 波动或成交额不够  
- `industry.lag` 不是领头行业  
- `rs.laggard` 组内相对落后  
- `pivot.cleared` / `pivot.approaching` / `pivot.failed`  
- `volume.thin` 穿过了但量不够  
- `follow.stall` / `follow.ok`

实盘对照例子：潍柴动力 `000338` 曾出现个股在「自然回撤」、上证在「自然回升」。自然回升属于下跌家族的反弹，总闸关闭，输出空仓。这是「先看大势」被执行，而不是个股形态单独说了算。

## 7. 接口、缓存与前端

### HTTP

- `GET /api/screen/livermore`  
  参数：`days`（10–180，主要作缓存键）、`top`、`kind`（`all` 或某个动作）、`code`、`refresh`、`workers`。  
  返回形态与 grind 相同：`status=running|done`，可轮询；`data.items[]` 为股票行。
- `GET /api/screen/livermore/stock?code=`  
  单股诊断，强制拉不复权日 K。

落盘键：`livermore_d{days}-c{code}-{CACHE_TAG}.json`，`CACHE_TAG=lv1`。算法改阈值后换 tag，旧结果自动作废。盘中沿用开盘后算过的结果，收盘后沿用到下一交易日开盘（`analysis.persist.is_fresh`）。

### 命令行

```text
python -m analysis.livermore 000338
python -m analysis.livermore --kind probe --top 30
```

在 `backend/` 目录运行。

### 前端

研判页 `/analysis` 增加页签「趋势分析」（`view=trend`）。卡片展示动作、六栏、相对大盘、组内排名、跟随状态、原因码。筛选按钮对应六个动作。前端只展示引擎结果，不二次改写 `action`。

## 8. 和现有研判的边界

| 模块 | 角色 |
|---|---|
| 行业轮动 `rotation` | 输入：谁是领头三级。趋势引擎只读缓存 |
| 阴跌/横盘 `grind` | 不直接调用；箱体时长由六栏 `reaction_days` 近似 |
| 阴跌→涨停 `decline` | 不接入动作。涨停突破只是另一种「穿过」，须再过六栏和失败检测 |
| 巴菲特 / 八看 agent | 另一条轴。两边分数互不引用 |

排序优先级：试探 → 加码 → 持有 → 等待 → 离场 → 空仓，同组内再按组内排名、20 日涨幅。真正接近他方法的集合是 **试探 / 加码 / 持有**；若这三类很多，说明阈值太松，应先收紧而不是加模型。

## 9. 尚未覆盖的思想

下列仍是人的纪律或后续版本，**当前引擎没有**：

- 真实账户上的试探仓份数、最多三档金字塔、按持仓而不是按日 K 启发式加码  
- 空仓等待的「下一笔什么时候才允许」的交易日历（只有每日快照）  
- 做空对称动作（A 股实现目前只开多闸门）  
- 用 LLM 写「为什么是试探」的说明报告（刻意后置）  
- 把 6 点 / 3 点按每只股票的个性再校准（现在全市场共用一套 ATR 倍数）

利弗莫尔亏大钱，往往不是规则太少，而是没执行。系统能做的是把「现在处于哪一栏、过没过关键点、大盘允不允许」算清楚；能不能空得住、砍得掉，仍然在使用者。
